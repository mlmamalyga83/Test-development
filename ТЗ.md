## 1. Анализ задания

### Задача 1 — unit-tests (обязательная)
**Что требуется:** Написать unit-тесты с параметризацией на 3 задания из модуля «Основы языка программирования Python», используя свои решения домашних заданий.

**Ключевые требования:**
- Использовать существующий код студента (предыдущие ДЗ)

- Обязательно применить параметризацию
- Оформить в виде unit-тестов (через `unittest`)

**Выбранные 3 задания:**
| № | Откуда | Что именно | Почему |

### Задача 3 — Selenium (дополнительная)

## 3. Детальные тест-кейсы

### 3.1. test_unit.py — 3 группы тестов

**Группа 1: `TestFlatGenerator`** (итераторы/генераторы)
- `test_flat_generator_simple` — одноуровневый список списков
- `test_flat_generator_nested` — многоуровневая вложенность
- `test_flat_generator_empty` — пустые списки внутри
- `test_flat_generator_mixed_types` — смешанные типы (строки, числа, None, bool)
- `test_flat_generator_deep_nesting` — глубокая вложенность [[[[['!']]]]]
- `test_flat_generator_returns_generator` — проверка типа GeneratorType
- Параметризация: через `@parameterized.expand` — 6+ кейсов с разными структурами списков

**Группа 2: `TestLoggerDecorator`** (декораторы)
- `test_logger_default_path` — декоратор без аргумента пишет в main.log
- `test_logger_custom_path` — декоратор с путём пишет в указанный файл
- `test_log_content` — в логе есть: дата, время, имя функции, аргументы, результат
- `test_sum` — декорированная summator работает правильно
- `test_div` — декорированная div работает правильно
- Параметризация: через `@parameterized.expand` — кейсы с разными аргументами (int, float)

**Группа 3: `TestCleanPhones`** (регулярные выражения)
- `test_standard_phone` — +7(123)456-78-90
- `test_phone_with_eight` — 8(123)456-78-90
- `test_phone_without_parentheses` — +7 123 456-78-90
- `test_phone_with_extension` — +7(123)456-78-90 доб.1234
- `test_phone_with_ext_variations` — доб., ext., без точки
- `test_phone_with_dashes` — различные варианты расстановки тире
- `test_empty_phone` — пустая строка
- `test_invalid_phone` — невалидный номер (не меняется)
- Параметризация: через `@parameterized.expand` — 10+ кейсов

### 3.2. test_api.py — Яндекс.Диск REST API

**Класс: `TestYandexDiskAPI`**
- `setUpClass` — загрузка токена из переменной окружения `YA_DISK_TOKEN`
- `test_create_folder_success` — создание папки → код 201
- `test_folder_in_list` — после создания папка есть в списке файлов
- `test_create_existing_folder` — повторное создание → код 409
- `test_create_folder_no_auth` — без токена → код 401
- `test_create_folder_invalid_name` — недопустимое имя → код 400
- `tearDown` — удаление созданной папки (очистка)

**Используемые эндпоинты:**
- `PUT https://cloud-api.yandex.net/v1/disk/resources` — создание папки
- `GET https://cloud-api.yandex.net/v1/disk/resources` — получение метаинформации
- `DELETE https://cloud-api.yandex.net/v1/disk/resources` — удаление (в tearDown)

### 3.3. test_selenium.py — Яндекс.Паспорт (доп.)

**Класс: `TestYandexPassportAuth`**
- `setUp` — инициализация WebDriver (Chrome), неявное ожидание 10с
- `test_page_loads` — страница загружается, есть форма ввода логина
- `test_login_input_exists` — поле для ввода логина присутствует
- `test_submit_button_exists` — кнопка «Войти» есть на странице
- `test_incorrect_login_shows_error` — ввод невалидного логина → сообщение об ошибке
- `tearDown` — закрытие браузера

## 4. Стиль кода (чтобы выглядело как работа студента)

- **Комментарии на русском** — краткие, по делу (как в предыдущих ДЗ)
- **Имена переменных** — английские, осмысленные
- **Структура тестов** — `unittest.TestCase`, `setUp`/`tearDown`
- **Параметризация** — через `parameterized.expand` (явно указать импорт)
- **Работа с токеном** — через `os.getenv()` и `.env` (как в ДЗ по ООП)
- **Обработка ошибок** — `try/except` и `assertRaises` там, где нужно
- **Нет излишнего ООП** — где можно функцией, там функция
- **Никаких продвинутых фич** — только то, что проходили на курсе

## 6. Порядок сдачи

1. Убедиться, что все файлы на месте
2. Установить зависимости: `pip install -r requirements.txt`
3. Запустить тесты Задачи 1: `python -m unittest test_unit.py -v`
4. Запустить тесты Задачи 2: `python -m unittest test_api.py -v`
5. (если делал) Запустить тесты Задачи 3: `python -m unittest test_selenium.py -v`
6. Убедиться, что все тесты проходят
7. Загрузить в LMS / отправить преподавателю
